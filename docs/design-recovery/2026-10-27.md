## Repository-specific records

### D24 — Content Weaver / Narrative Loom: composing stories as editable systems

**Use when:** When recovering Content Weaver, Narrative Loom, brand voice, article/story composition, generative headers, or multimedia blocks.

[Recovered intent] The README describes narrative generation, brand voice, artist statements, grant/proposal writing, and weaving content threads. Current tree evidence also reveals a Narrative Loom artifact with an editor canvas, sidebar, article preview, Three.js block, themes, and media assets. The generic README underrepresents that authoring-surface direction.

[Design DNA — inferred] A composed editorial workspace: readable content at the center, contextual tools at the edge, interchangeable thematic framing, and multimedia that supports the story. A visually rich canvas should remain editable and exportable rather than a screenshot of a document.

[Observed boundary] The inspected CanvasView has theme-dependent banners, desktop/mobile display widths, and visible block controls. This does not establish persistence, a functioning generation service, drag/reorder, collaborative editing, or export fidelity. Multiple migration/artifact folders require a current entry-point decision.

[Repair resolution — proposed] Define a canonical document/block schema before adding more visual controls. Separate document content, view/theme, generation candidates, citations, asset rights, revision history, and export adapters. Make each apparent control functional or explicitly a preview. Preserve user voice and inference-led writing rather than homogenizing it into generic AI copy.

[Reimagined horizon] An evidence-aware narrative instrument for stories, portfolio cases, proposals, campaign materials, and sensory editorial experiences. Generative suggestions remain editable candidates.

[Carry-forward test] A document containing text, image, quote, and one optional interactive block survives editing, reordering, save/reload, mobile preview, and a plain export without losing meaning or provenance.

## Practical continuation contract

1. Re-read current repository instructions and source before implementation. The baseline above identifies this publication, not a permanent execution HEAD.
2. Retain the full design horizon separately from the current demonstrator. Name what the demonstrator preserves, approximates, defers, or cannot prove.
3. Map tokens and controls to actual consumers with explicit units, ownership, accessible alternatives, and observable effect.
4. Complete the relevant interaction/error/cancellation states before promoting a reusable component.
5. Pair source/runtime checks with human correspondence review against the actual visual inspiration.
6. Keep proposed repairs unexecuted until a later implementation records its own revision, checks, and evidence.
